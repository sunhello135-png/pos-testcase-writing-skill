# pos-testcase-writing

用于编写、优化和合并 **ProcessOn `.pos` 测试用例库**的中文 Agent Skill。它把需求澄清、模块划分、用例写法、优先级和合并校验整理成一套约定，帮助 AI 按统一口径维护用例库。

完整规则见 [SKILL.md](./SKILL.md)。本仓库提供写作与维护规范，实际读取、修改和校验 `.pos` 文件由加载 skill 的 AI 工具执行；仓库目前没有独立生成器、校验脚本或预置用例库。

## 用途

- **补充需求用例**：先读取现有用例库的目标子树，复用已有模块和分组，减少重复覆盖。
- **优化用例结构**：按产品页面、Tab 和功能区组织模块，将一条完整业务流程收拢为一条用例。
- **合并增量用例**：在宿主 `.pos` 中原地追加，保留原节点 ID，默认保留已有标题、内容和图标。
- **维护多变体功能**：按身份、来源或渠道划分主干与差异分支，完整覆盖共性能力，单独描述差异。
- **处理改版与口径冲突**：明确移动、删改和保留范围，记录冲突、受影响用例与校验结果。

适合已有 ProcessOn 思维导图用例库、需要持续迭代维护的测试工作。使用前准备好可读取的需求资料、页面或原型说明，以及目标 `.pos` 文件；补充已有用例时，最好同时给出目标节点路径。

## 核心约定

| 方面 | 约定 |
| --- | --- |
| 编写顺序 | 先读取宿主库，再逐元素过逻辑维度清单，集中澄清不确定项，确认后生成 |
| 逻辑维度清单 | 页面上每个元素逐格填规则：列表的收录范围、排序、分组、默认条数与加载更多阈值；搜索的范围、匹配字段与方式；统计字段的定义、主体、时间口径与展示。填不出的格子先问，交付时附覆盖表 |
| 模块划分 | 跟随页面、Tab、功能区的信息架构，跨页签公共内容单独组织；每个页签单独过维度清单，不写「同上」 |
| 用例链路 | 入口 → 操作 → 结果 → 下游校验写成一条完整用例 |
| 节点格式 | 跟随宿主库多数模块：前置、操作、预期各一个节点，操作用 → 串联，预期用 `<br>` 分行 |
| 预期格式 | 每条断言使用 `n) 维度 ｜ 内容`，称为 A 记法 |
| 前置条件 | 写清数据与环境、角色、入口 |
| 正常场景 | 主链路 E2E 为 P0，辅助行为为 P1 |
| 异常场景 | 默认 P2；数据丢失、脏数据残留、权限越权或计费归属错误等为 P1，不使用 P0 |
| 边界场景 | 一律 P2 |
| 合并保护 | 默认保留原节点 ID、标题、内容和图标；重挂载节点记录清单，已有用例删改需授权 |
| 交付语言 | 中文，交付文档署名 Sun |

需求中的上限值、权限矩阵和提示文案需要有明确依据；可由用户确认的内容应在生成前问清。只有用户也无法回答、确实需要产品确认的事项才进入待确认清单。用户明确要求先出稿时，先列出采用的假设。

## 安装方法

以下以 **Claude Code** 为例。个人 skill 放在 `~/.claude/skills/`，项目 skill 放在项目根目录的 `.claude/skills/`；也可以通过 `/skill-name` 显式调用。目录规则与调用方式见 [Claude Code 官方文档](https://code.claude.com/docs/en/skills)。

### 准备条件

- 已安装 Git 和支持本地 `SKILL.md` 的 AI 工具。
- 使用 Claude Code 时，需要能读取需求资料并操作本地文件；通过 Python 处理 `.pos` JSON 时需要 Python 3。
- 本仓库为**公开仓库**，可直接克隆。

以下命令适用于 macOS / Linux 的终端。

### 方式一：个人安装

安装到个人目录，供多个项目使用：

```bash
mkdir -p ~/.claude/skills
git clone https://github.com/sunhello135-png/pos-testcase-writing-skill.git ~/.claude/skills/pos-testcase-writing
```

安装后应存在：

```text
~/.claude/skills/pos-testcase-writing/
├── README.md
└── SKILL.md
```

仓库名是 `pos-testcase-writing-skill`，安装目录和 skill 名称使用 **`pos-testcase-writing`**。

### 方式二：项目安装

如果只想在某个项目中使用，在该项目根目录执行：

```bash
mkdir -p .claude/skills
git clone https://github.com/sunhello135-png/pos-testcase-writing-skill.git .claude/skills/pos-testcase-writing
```

此方式会在项目中创建独立的 Git 仓库。若要将 skill 随宿主项目一起提交，可改为将本仓库的 `SKILL.md` 手动复制到 `.claude/skills/pos-testcase-writing/SKILL.md`，由宿主项目管理该文件。

### 已有安装与更新

如果目标位置已有同名目录，`git clone` 会停止。先检查它是 Git 安装还是手工复制，并保留本地修改。

通过上面的个人安装命令克隆后，可执行：

```bash
git -C ~/.claude/skills/pos-testcase-writing pull --ff-only
```

项目安装时，将命令中的路径换为 `.claude/skills/pos-testcase-writing`。手工复制的安装不支持直接 `git pull`，需要比较本地与仓库中的 `SKILL.md` 后更新。

## 使用示例

安装后，在 Claude Code 对话中输入 `/pos-testcase-writing`，并提供具体任务与实际文件路径。下面的路径和业务内容均为示例，使用时替换为自己的资料。

### 示例一：给已有用例库补充需求

```text
/pos-testcase-writing

需求文件：./docs/共享管理需求.md
宿主用例库：./cases/产品测试用例.pos
目标位置：共享管理 → 我的 Agent → 共享给好友

请先打印目标功能点的完整子树，检查已有覆盖和重复断言，
再集中列出需要我确认的问题。确认后，将新增用例合并到宿主文件，
保留原节点 ID、标题、内容和图标，并交付 .pos 与中文变更说明。
```

### 示例二：优化重复与多变体结构

```text
/pos-testcase-writing

宿主用例库：./cases/文件导入.pos
目标功能点：文件管理 → 导入
需求说明：./docs/导入渠道差异.md

请检查「导入、进度、结果归集、导入后读取」是否属于同一条链路，
将可以合并的新用例按完整流程组织。
对本地文件与云盘两个来源，使用主干加差异分支，并补充能力范围对照。
已有节点只允许移动；如需修改原内容，请先列出原因和清单供我确认。
```

### 示例三：补充 Bug 回归与异常恢复

```text
/pos-testcase-writing

宿主用例库：./cases/导入回归.pos
Bug 记录：./docs/bug-123.md
目标位置：文件管理 → 导入 → 异常恢复

请根据 Bug 记录补充回归用例。
标题和预期描述修正后的正确行为，备注标记【Bug 回归：#123】。
覆盖失败后的恢复重试、最终结果校验及无半成品残留，
并按 skill 的规则确定优先级。对不明确的行为先问清再写。
```

## 预期交付

每次任务交付更新后的 `.pos` 文件及一份 Markdown 说明。说明包括：

1. **需求与落点对照**：需求对应的模块、分组和用例数量；有重构时附结构树。
2. **元素覆盖表**：页面元素 × 逻辑维度 → 用例，确认排序、条数、匹配字段、统计口径等规则都有断言。
3. **总量前后对比**：节点数、用例数、图标数，以及 P0 / P1 / P2 分布。
4. **合并校验**：重复 ID、原节点丢失、原标题变化、父节点关系、空标题、新引入重名、A 记法与节点格式问题。
5. **关键断言与已定口径**：反向断言、身份分离、能力对照、成对差异、线上已复现的不一致等。
6. **既有用例修订清单**：需修订的位置与原因；有授权删改或节点重挂载时逐条列明。
7. **待产品确认事项**：仅记录确实需要产品回答的问题，并保留上轮尚未解决的事项。

具体规则和例外以 [SKILL.md](./SKILL.md) 为准。生成的文件仍需在实际使用的 ProcessOn 环境中导入验收；仓库本身不包含导入成功的自动验证机制。
